## Git Workflow

Every task follows the same workflow:

```
main
   │
   ├── week-01-repository-setup
   ├── week-01-semantic-html-accessibility
   ├── week-01-box-model-cascade-specificity
   ├── week-02-positioning-flexbox-grid
   └── ...
```

Steps:

1. Create a feature branch.
2. Complete the practical.
3. Commit changes.
4. Push the branch.
5. Create a Pull Request.
6. Review and merge into `main`.

## Repository Rules

- Never work directly on the `main` branch.
- One topic = One branch.
- Every feature must have its own Pull Request.
- Keep commits meaningful.
- Write clean and readable code.
- Update documentation whenever necessary.
